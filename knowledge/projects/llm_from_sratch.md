# LLM From Scratch — Building a Mini GPT with PyTorch

## Project Overview

LLM From Scratch is a comprehensive project that builds the fundamental components of a GPT-like language model from the ground up using PyTorch, without relying on high-level LLM frameworks. The project focuses on understanding the complete pipeline from raw text through tokenization, embeddings, attention mechanisms, Transformer architecture, training, and text generation. The repository progressively implements these components through a sequence of practical labs, providing a hands-on understanding of how large language models work internally.

## Problem Context

Large Language Models such as GPT are usually consumed through high-level APIs, which can make it difficult to understand what happens internally. The goal of this project was to build the fundamental components of a GPT-like language model from scratch in PyTorch, without relying on high-level LLM frameworks. By implementing the complete pipeline from text processing through tokenization, embeddings, attention, Transformer, training, decoding, and text generation, the project provides deep insight into the internal mechanisms of modern language models.

## Primary Objectives

The main objectives were to understand how language models process text, build a vocabulary and tokenizer from scratch, implement token embeddings and positional encoding, understand and implement self-attention, implement multi-head attention, build feed-forward neural networks, implement residual connections and layer normalization, construct Transformer encoder and decoder blocks, build a complete Transformer architecture, implement the training loop with backpropagation, implement validation and model evaluation, implement greedy decoding and beam search, implement text generation, implement a BPE tokenizer, apply label smoothing, implement learning-rate scheduling, experiment with mixed-precision training, and prepare a larger dataset pipeline for training a small GPT model. The repository contains dedicated labs from lab01 through lab28 covering these concepts progressively, with additional labs for dataset preparation.

## System Architecture

### Bottom-Up Transformer Architecture

The project follows a bottom-up Transformer architecture where raw text flows through text preprocessing to tokenization, producing token IDs. These IDs pass through token embeddings combined with positional encoding to create input representations. The Transformer blocks process these representations through self-attention mechanisms and feed-forward networks, with residual connections and layer normalization. The complete Transformer model produces logits that feed into decoding strategies including greedy search and beam search, ultimately generating the final text output.

### Transformer Component Implementation

Individual Transformer components were implemented independently to understand their mathematical and computational behavior. These include ScaledDotProductAttention for computing attention scores, SelfAttention for processing sequences against themselves, MultiHeadAttention for parallel attention heads, CrossAttention for attending between different sequences, FeedForwardNetwork for processing attention outputs, TransformerEncoder for encoding input sequences, and TransformerDecoder for generating output sequences. Each component was implemented from scratch using PyTorch's nn.Module.

### Complete Transformer Architecture

A complete Transformer architecture was assembled from the previously implemented components. The training implementation uses a configurable architecture with parameters including embedding dimension, number of attention heads, hidden dimension, number of encoder layers, number of decoder layers, dropout rate, learning rate, and number of epochs. For example, the training lab defines an embedding dimension of 100, four attention heads, hidden dimension equal to four times the embedding dimension, and configurable encoder and decoder depth.

### Mini GPT Architecture

The final direction of the project is an autoregressive GPT-style language model capable of generating text from a sequence of tokens. The repository also contains a models/transformer.pth checkpoint generated by the Transformer training pipeline, demonstrating a working implementation.

### Dataset Pipeline

The first Transformer experiments use two small text datasets, sample.txt and sample_fr.txt, to demonstrate English and French text processing and Transformer training. The training pipeline performs text cleaning, vocabulary construction, token encoding, sequence creation, PyTorch Dataset creation, DataLoader preparation, and Transformer training. The training implementation creates separate English and French vocabularies, encodes the text into token IDs, creates sequence datasets, and feeds them through PyTorch DataLoaders.

### Small-GPT Dataset Pipeline

A second dataset pipeline was added for moving toward a more realistic small-GPT training setup. It includes dataset downloading, dataset inspection, cleaning, quality filtering, deduplication, train and validation splitting, and BPE tokenizer training. These stages are implemented in small_gpt from lab29 through lab35, providing a complete data preparation pipeline for training a small language model.

## Key Challenges

### Understanding Attention
One of the main challenges was translating the mathematical formulation of attention into PyTorch operations. The implementation required understanding the attention formula where Attention(Q,K,V) equals softmax(QKᵀ divided by √dₖ)V, requiring careful management of tensor dimensions, matrix multiplication, scaling, and masking operations.

### Managing Tensor Shapes
Transformer architectures involve several dimensions simultaneously including batch size, sequence length, embedding dimension, number of heads, and vocabulary size. Maintaining the correct tensor shapes across attention, encoder, decoder, and output layers was a major implementation challenge that required careful dimension tracking and transformation.

### Causal Masking
For autoregressive generation, the model must not access future tokens. The implementation requires masking future positions during decoder self-attention to ensure the model only attends to previous tokens, preserving the autoregressive property of language generation.

### Training Stability
Training a Transformer from scratch requires appropriate learning rate, dropout, loss function, initialization, sequence length, batch size, and optimization strategy. The training pipeline became progressively more sophisticated by introducing label smoothing, learning-rate scheduling, and mixed precision to improve training stability and performance.

### Tokenization
A basic word-level tokenizer is easy to implement but has important limitations especially for unknown words. Implementing BPE provided a more realistic approach to subword tokenization and became an important step toward the small-GPT pipeline, enabling better handling of rare and unseen words.

### Dataset Quality
Moving from toy datasets toward a real small-GPT dataset introduced additional challenges including dataset cleaning, quality filtering, deduplication, train-validation splitting, and tokenizer training. The repository separates dataset preparation into dedicated labs rather than directly feeding raw text into the model.

## Lessons Learned

### Tokenization Is Fundamental
The quality of the tokenizer directly affects the representation of language and the efficiency of model training. BPE tokenization provides a practical balance between vocabulary size and coverage of rare words, making it essential for language model development.

### Attention Is the Core of Modern Transformers
Understanding Query, Key, Value, masking, and multi-head attention makes the Transformer architecture much easier to understand. Attention mechanisms enable models to focus on relevant parts of the input, making them powerful for sequential data processing.

### Tensor Dimensions Are Critical
Most Transformer implementation bugs can be traced to incorrect tensor shapes or incompatible dimensions. Careful dimension tracking and testing are essential for successful Transformer implementation.

### A Transformer Is a System of Components
A GPT model is not simply an attention layer. It combines embedding, positional information, multi-head attention, feed-forward networks, residual connections, layer normalization, and output projection into a cohesive architecture. Understanding each component is essential for understanding the complete system.

### Data Quality Matters
Building a language model is not only about architecture. Dataset cleaning, filtering, deduplication, splitting, and tokenization are equally important for model performance. High-quality training data is essential for learning meaningful language representations.

### Training Requires Optimization Techniques
Label smoothing, learning-rate scheduling, dropout, and mixed-precision training can significantly improve the practicality and stability of training. These techniques help prevent overfitting, improve convergence, and enable efficient training on available hardware.

### Building from Scratch Improves Understanding
Implementing each component manually provides a deeper understanding of how GPT-like systems work internally compared with simply calling a pretrained LLM API. This hands-on approach reveals the complexity and elegance of modern language models.
